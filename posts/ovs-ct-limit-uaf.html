Fixing a use-after-free in Open vSwitch conntrack zone limits

First posted 2026-07-22 · merged into mainline 2026-08-24 · openvswitch, RCU, netns teardown

Open vSwitch lets you cap the number of conntrack entries per zone — the "CT limit" feature. The per-zone accounting state lives in kernel memory attached to the network namespace. This post is about a use-after-free in the way that state was torn down, and why the correct fix turned out to be a restructuring of the teardown rather than another NULL check.

The bug

Two sides touch the CT limit state with different locking:

  • The datapath reads it on every packet that goes through a conntrack action — under RCU, in ovs_ct_execute(), no mutex allowed on this fast path.
  • Netns teardown freed that same state while holding ovs_mutex, in the pernet exit callback.

The CT limit pointer was never removed from readers before being freed, and there was no RCU grace period between the free and the readers. So a packet hitting the datapath at the wrong moment during namespace teardown would dereference freed memory:

slab-use-after-free in ovs_ct_execute()

What makes this bug serious is who can reach it: an unprivileged user inside a user namespace can create their own network namespace, configure CT limits, and tear the namespace down. No capabilities on the host required.

Why the obvious fixes are wrong

The tempting one-liner — "just check for NULL in the reader" — doesn't work here. The reader never saw a NULL pointer; it saw a stale pointer to already-freed memory. Adding NULL checks after the free has already happened fixes nothing. The real invariant that was missing: a pointer that is read under RCU must be unpublished and grace-period-protected before its memory is released.

The fix

The patch restructures the lifetime of the CT limit state around that invariant:

  • Publish the CT limit pointer through RCU, so all readers and writers agree on how it appears.
  • On teardown, remove the state from the visible lists first (in the pernet .pre_exit callback, still under ovs_mutex), then wait for readers.
  • Defer the actual free to the pernet .exit callback. The pernet core already guarantees an RCU grace period between .pre_exit and .exit, so the free happens after every in-flight reader is done — no extra synchronization needed.
  • Keep ovs_mutex around individual CT limit updates, and take the RCU read-side lock where the netlink GET handler walks the limit lists.

One subtlety that came up during review: the netlink command handlers (SET/DEL/GET) do not need new NULL checks, even though the state can now disappear. A userspace netlink socket holds an active reference to its network namespace while a request is being processed, so the pernet exit path cannot run concurrently with netlink operations for that namespace.

Upstream

The fix was reviewed by Ilya Maximets and applied by Jakub Kicinski, landing in mainline as 403f96c32c9e ("openvswitch: Fix CT limit teardown use-after-free"), with a Fixes: tag back to 11efd5cb04a1, the commit that introduced conntrack zone limits — and a stable backport.

Takeaway: when the fast path is RCU and the slow path frees, the bug is rarely in the reader. It's in the teardown that forgot RCU existed.
