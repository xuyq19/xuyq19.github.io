Linux Kernel 安全修复提交记录

2025.04 · 徐宇奇 · 阅读约 10 分钟

2024-2025 年间，我向 Linux Kernel 社区提交了 6 个安全修复 Patch，涵盖 Bluetooth、WiFi、BPF、网络（RDS、rxrpc）等子系统。本文记录这些漏洞的发现和修复过程，作为给后来者的一份参考。

提交概览

日期 子系统 Patch 标题
2025-05-29 Bluetooth hci_sync: reject oversized Broadcast Announcement prepend
2025-05-29 WiFi (nl80211) reject oversized EMA RNR lists
2025-05-27 BPF (sockmap) fix tail fragment offset in bpf_msg_push_data

2025-04-13 WiFi (cfg80211) reject duplicate wiphy cipher suite entries
2025-04-08 Network (rxrpc) reject undecryptable rxkad response tickets

漏洞类型分析

这 6 个 Patch 都指向同一个根本问题：输入验证缺失。在底层网络协议和驱动代码中，当用户空间传递的数据包大小、数组长度或配置项超过预期时，内核没有进行充分的边界检查，导致潜在的安全风险。

提交流程

Linux Kernel 的 upstream 提交流程对于新手来说有一定的门槛：

  1. 漏洞定位：通过代码审计或 fuzzing 发现可疑的边界检查缺失
  2. 修复验证：编写修复代码，在本地编译并通过内核测试套件（kselftest）
  3. 邮件列表：向对应子系统的维护者发送 patch，抄送相关邮件列表（如 linux-bluetooth@vger.kernel.org）
  4. Code Review：维护者 review 代码，提出修改意见（通常 1-3 轮）
  5. 合入：维护者将 patch 合入子系统 git tree，最终进入 Linus 的 mainline

经验总结

  • 邮件格式很重要：使用 git format-patch 生成的格式，确保 Subject 前缀正确（如 [PATCH net]）
  • 找对人：MAINTAINERS 文件里能找到每个子系统的维护者和邮件列表
  • 保持耐心：从提交到合入通常需要 1-4 周，大的子系统可能更久
  • 测试要充分：内核社区对回归测试要求很严格，确保修复不会引入新问题
