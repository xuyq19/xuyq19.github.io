Rejecting duplicate cipher suites in wiphy_register()

First posted 2026-04-13 · merged into mainline 2026-04-28 · wifi, cfg80211, WEXT

When a wireless driver registers with cfg80211, it describes its capabilities in a struct wiphy — including the list of supported cipher suites. This post is about what happens when that list contains duplicates, and why the right place to reject them is at registration, not in every consumer.

The bug

Duplicate entries in wiphy->cipher_suites don't describe any additional capability — a cipher either is or isn't supported. But cfg80211 accepted them silently, leaving each consumer of the list to cope on its own.

One consumer that couldn't cope: the WEXT compatibility code. The ancient SIOCGIWRANGE ioctl reports supported encryptions through a fixed-size array, iw_range::encoding_size. The compat code appends one WEP key length for every WEP cipher entry it sees. Repeat a WEP entry enough times in the wiphy description, and the appends walk straight past the end of the array — a stack/heap-adjacent overflow triggered simply by registering a malformed device description.

Why not fix WEXT?

Patching the WEXT code to deduplicate would have fixed that overflow, but it leaves the underlying problem in place: a malformed input is accepted at the boundary and every future consumer has to remember to defend itself. The better invariant is to make the input itself illegal.

The fix

Validate the cipher suite list once, in wiphy_register(), and fail early:

static bool wiphy_cipher_suites_valid(const struct wiphy *wiphy)
{
	int i, j;

	if (wiphy->n_cipher_suites && !wiphy->cipher_suites)
		return false;

	for (i = 0; i < wiphy->n_cipher_suites; i++)
		for (j = 0; j < i; j++)
			if (wiphy->cipher_suites[i] ==
			    wiphy->cipher_suites[j])
				return false;

	return true;
}

A malformed wiphy description now fails registration with -EINVAL, right where the driver author will notice it, instead of corrupting memory in a legacy ioctl handler far away from the actual mistake. The list is short and registration is a cold path, so the O(n²) check costs nothing in practice.

Upstream

Merged by Johannes Berg as 7187d145d904 ("wifi: cfg80211: reject duplicate wiphy cipher suite entries").

Takeaway: validate invariants at the boundary where data enters the subsystem. One check at registration beats N defensive checks scattered across consumers — including the ones nobody has written yet.
